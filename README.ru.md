<p align="center"><a href="README.md">English</a> · Русский</p>

ИИ-агенты забывают. Каждая новая сессия теряет договорённости, снова предлагает отвергнутые подходы и пересказывает свой прогресс так, что с каждым разом он искажается всё сильнее. Engram хранит эти знания в структурированном файле `.engram` под версионным контролем. Вы редактируете его в быстром десктопном приложении, а агенты читают и обновляют его через Model Context Protocol, поэтому вы работаете с одним источником правды.

## Скачать

Последняя версия находится на [странице релизов](https://github.com/liwidale/engram/releases/latest).

| Платформа | Файл | Требования |
| --- | --- | --- |
| macOS | `Engram-<версия>-macos-universal.zip` | macOS 14 или новее, Apple silicon или Intel |
| Windows | `Engram-<версия>-windows-x64-setup.exe` или портативный `.zip` | Windows 10 или новее, x64 |
| Linux | `engram-<версия>-linux-x86_64.tar.gz` | glibc 2.35 или новее, X11 или Wayland |

- **macOS:** распакуйте архив и перенесите `Engram.app` в «Программы».
- **Windows:** запустите установщик. Он ставит приложение для вашей учётной записи и регистрирует тип файлов `.engram`.
- **Linux:** распакуйте архив и запустите `./install.sh`. Скрипт ставит приложение в `~/.local` и регистрирует тип файлов `.engram`; для установки на всю систему добавьте `--prefix /usr/local` и запустите через `sudo`.

В каждую сборку входит `engram-mcp` — MCP-сервер, к которому подключаются агенты.

## Что вы получаете

- **Память проекта.** Правила, технологии, архитектурные инварианты и соглашения в Markdown с живым предпросмотром. Если заменить запись новой, старая получает метку `[SUPERSEDED]`, остаётся в истории и больше не попадает к агентам.
- **Карта архитектуры.** Модули, сервисы и базы данных с зависимостями в виде интерактивного графа. Engram раскладывает его автоматически, подсвечивает циклические зависимости и запоминает, куда вы перетащили узлы.
- **Журнал решений.** Архитектурные решения с контекстом, самим решением и каждой отвергнутой альтернативой с причиной. Агенты видят отвергнутые варианты как тупики и перестают их предлагать.
- **Хранилище промптов.** Промпты проекта с плейсхолдерами `{{variable}}`. Скопируйте промпт с заполненными переменными или дайте агенту получить его самому.
- **Сборщик контекста.** Опишите задачу, и Engram отранжирует память, решения и архитектуру по релевантности, а затем уложит лучшее в бюджет токенов. Любой элемент можно принудительно включить или исключить, а результат скопировать в XML.
- **Здоровье контекста.** Проверка файла по вашему коду. Она находит битые пути, ссылки на удалённые записи, устаревшие решения, которые всё ещё используются, правила, противоречащие друг другу, и память, рекомендующую то, что отвергнуто решением.
- **Передача агенту.** Структурированный чекпоинт: текущая цель, проверенный прогресс с путями к файлам, рабочая память и следующий атомарный шаг. Он заменяет пересказы чата между сессиями.
- **Живое обновление.** Когда агент меняет файл, открытое окно обновляется за доли секунды.
- **Клавиатура прежде всего.** Палитра команд ищет по всем командам и записям, у каждого модуля есть свой шорткат.

## Первые шаги

1. Откройте Engram и выберите **New project memory**. Сохраните файл в корне репозитория, например `project.engram`.
2. Добавьте несколько записей: стек, правила, которым должно следовать каждое изменение, и то, в чём агенты постоянно ошибаются.
3. Нажмите **Copy MCP config** в панели инструментов и вставьте фрагмент в настройки MCP вашего агента (см. [Настройка](#настройка)).
4. Начните сессию агента. Он читает `engram://handoff`, вызывает `build_context` со своей задачей и записывает новые решения по ходу работы.

Файл можно создать и из командной строки:

```bash
engram-mcp init project.engram --name "My project"
```

## Каждый день

| macOS | Windows и Linux | Действие |
| --- | --- | --- |
| `⌘K` | `Ctrl+K` | Палитра команд |
| `⌘1`–`⌘7` | `Ctrl+1`–`Ctrl+7` | Переключить модуль |
| `⌘S` | `Ctrl+S` | Сохранить правки (редакторы сохраняют и сами) |
| `⌘R` | `Ctrl+R` | Перечитать с диска |
| `⇧⌘N` | `Ctrl+Shift+N` | Новая запись памяти |
| `⇧⌘D` | `Ctrl+Shift+D` | Записать решение |
| `⇧⌘H` | `Ctrl+Shift+H` | Проверить здоровье контекста |
| `⇧⌘M` | `Ctrl+Shift+M` | Скопировать конфигурацию MCP |

- **Несколько проектов.** Каждый файл открывается в своей вкладке. В Windows и Linux файлы `.engram` можно перетащить прямо в окно.
- **Храните файл в Git.** Формат — обычный JSON, где каждая строка Markdown занимает отдельный элемент массива, поэтому диффы и слияния остаются читаемыми. Добавьте `*.engram.lock` в `.gitignore`.
- **Проверка в CI.** `engram-mcp audit --file project.engram` завершается с кодом 1, если проверка нашла ошибки.

## Настройка

### Подключение агента

**Copy MCP config** создаёт такой фрагмент, уже указывающий на установленный `engram-mcp` и открытый файл:

```json
{
  "mcpServers": {
    "engram-my-project": {
      "type": "stdio",
      "command": "/Applications/Engram.app/Contents/MacOS/engram-mcp",
      "args": ["--file", "/path/to/my-project/project.engram"]
    }
  }
}
```

Вставьте его в `claude_desktop_config.json`, в `.mcp.json` проекта или в настройки MCP в Cursor и Windsurf. Для Claude Code то же меню копирует готовую команду `claude mcp add`.

Сервер предоставляет такие ресурсы и инструменты:

| Ресурсы | Инструменты |
| --- | --- |
| `engram://memory` | `build_context(task_description, max_tokens)` |
| `engram://architecture` | `upsert_memory(key, category, content, supersedes_key)` |
| `engram://decisions` | `add_architecture_node(id, type, dependencies)` |
| `engram://handoff` | `log_decision(context, decision, rejected_alternatives)` |
| `engram://prompts` | `update_handoff(objective, progress, working_memory, next_step)` |
| `engram://memory/{key}` | `audit_health(repo_root_path)` |
| `engram://decisions/{id}` | `get_prompt(name)`, `save_prompt(name, body)`, `deprecate_decision(id)` |

Промпты из хранилища также доступны как MCP-промпты.

### Связанная кодовая база

Проверка здоровья сверяет пути с папкой, в которой лежит файл `.engram`. Если код находится в другом месте, выберите **Change folder** в разделе Context health. Путь по возможности хранится относительно файла, поэтому файл остаётся переносимым.

### Язык

Интерфейс на английском, все строки готовы к переводу. В Windows и Linux язык можно задать переменной окружения `ENGRAM_LANG`.

## Приватность

Engram работает полностью на вашем компьютере. В нём нет аккаунтов, телеметрии, аналитики и сетевых запросов. `engram-mcp` читает и пишет только тот файл, который вы ему передали, а проверка здоровья только читает имена файлов в связанной папке.

## Решение проблем

- **macOS не открывает приложение.** Сборки подписаны ad hoc и не нотаризованы. Нажмите на `Engram.app` правой кнопкой, выберите **Открыть** и подтвердите.
- **Агент не видит сервер.** Проверьте, что путь в `command` существует и что агент перезапущен после изменения настроек. Запустите `engram-mcp --file <путь>` в терминале: он должен вывести название проекта и ждать ввода.
- **В Linux не открываются диалоги файлов.** Engram использует XDG desktop portal. Установите `xdg-desktop-portal` и портал для вашего окружения, например `xdg-desktop-portal-gtk` или `xdg-desktop-portal-kde`.
- **Проверка сообщает, что папка с кодом не найдена.** Связанную папку переместили или переименовали. Выберите **Change folder** в разделе Context health.
- **Правки агента не появляются.** Убедитесь, что агент и приложение работают с одним и тем же файлом. **Reload from disk** принудительно обновляет окно.

## Сборка из исходников

Нужен [Rust](https://rustup.rs) 1.89 или новее.

**macOS** (Xcode или Command Line Tools):

```bash
./build.sh                    # универсальное приложение в build/Engram.app
./build.sh --native --debug   # быстрая сборка для текущей архитектуры
./build.sh --test             # плюс тесты Rust и Swift
./build.sh --install          # копирует в /Applications и регистрирует тип файлов
```

**Windows и Linux:**

```bash
cd rust-core
cargo build --release -p engram-desktop -p engram-mcp
```

Готовые файлы — `target/release/engram` и `target/release/engram-mcp`. В Linux `packaging/linux/package.sh <версия>` собирает такой же архив, как в релизе.

Тесты на любой платформе запускаются командой `cargo test --workspace` в папке `rust-core`. Логотип, вордмарк и все иконки платформ генерирует `swift tools/make-icons.swift` на macOS.

## Как это работает

- **Один движок.** `engram-core` — библиотека на Rust, которая отвечает за формат файла, граф зависимостей, сборщик контекста и проверку здоровья. Приложение для macOS подключает её как статическую библиотеку через C-интерфейс, приложение для Windows и Linux использует её напрямую, а `engram-mcp` собирается из того же кода.
- **Один путь записи.** Каждое изменение, из приложения или от агента, — это операция внутри транзакции: заблокировать файл, прочитать его, применить изменение, проверить и атомарно заменить файл. Несколько приложений и агентов могут писать одновременно и не теряют изменения друг друга.
- **Живые обновления.** Приложение для macOS следит за файлом через событийный механизм ядра, а приложение для Windows и Linux сравнивает отпечаток файла два раза в секунду. В обоих случаях окно обновляется, только если содержимое на диске отличается от последнего прочитанного.
- **Ранжирование.** Сборщик контекста оценивает элементы по BM25, поднимает элементы, связанные с подходящими узлами архитектуры, ставит инварианты и правила выше заметок и заполняет бюджет токенов самыми релевантными элементами. Токены считаются в кодировке `o200k_base`.

Сам файл — читаемый JSON:

```json
{
  "format": "engram",
  "version": 1,
  "revision": 12,
  "project": { "name": "Shop", "created_at": "2026-11-23T08:15:17Z", "updated_at": "2026-11-23T09:02:41Z" },
  "memory": [
    {
      "key": "payments-idempotency",
      "category": "invariant",
      "status": "active",
      "content": [
        "Every payment mutation carries an idempotency key.",
        "Retries must never charge a customer twice."
      ],
      "files": ["services/payments/charge.ts"],
      "created_at": "2026-11-23T08:15:17Z",
      "updated_at": "2026-11-23T08:15:17Z"
    }
  ],
  "architecture": { "nodes": [] },
  "decisions": [],
  "prompts": [],
  "handoff": {}
}
```

## Структура проекта

```
rust-core/
  crates/engram-core/       Формат файла, граф, сборщик контекста, проверка здоровья, C-интерфейс
  crates/engram-mcp/        MCP-сервер и утилиты командной строки
  crates/engram-desktop/    Приложение для Windows и Linux
EngramApp/                  Приложение для macOS (SwiftUI)
packaging/                  Установщик для Windows и интеграция с рабочим столом Linux
branding/                   Логотип, вордмарк и сгенерированные иконки
tools/                      Генератор иконок
project.engram              Память проекта самого Engram
```

## Участие в разработке

Issues и pull requests приветствуются.

- Перед открытием pull request запустите `cargo fmt`, `cargo clippy --workspace --all-targets -- -D warnings` и `cargo test --workspace`.
- Изменения формата файла должны включать путь миграции для существующих файлов.
- Любое изменение файлов `.engram` проходит через операцию в `engram-core`; приложения и MCP-сервер никогда не пишут файл напрямую.
- Текст интерфейса проходит через слой перевода: `String(localized:)` в Swift и `tr()` в Rust.
